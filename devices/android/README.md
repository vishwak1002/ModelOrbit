# Android on-device POCs

Open this directory as an Android Studio project. `app/src/main/java/dev/modelorbit/executorch/` contains one shared `ModelAdapter` contract and distinct text generation, Parakeet TDT, and Whisper ASR execution paths. The text adapter covers the 0.6B, 1.7B, and 4B Qwen3 variants, SmolLM2-135M-Instruct, and Llama-3.2-1B-Instruct. The UI has a no-weight **Run fixture** action and a **Run on device** action. Native output is labeled `pass` only when the selected runner returns nonempty output. This is an execution smoke result, not a quality or benchmark claim. The app requests no `INTERNET` permission.

The cross-platform model IDs, experimental Whisper and Qwen3-VL records, immutable Hugging Face revisions, required files, and native blockers are in [`model-pocs.json`](./model-pocs.json). `Qwen3-VL-2B-Instruct` is shown as a blocked research lane: [ExecuTorch's Android PR](https://github.com/pytorch/executorch/pull/17572) and [Optimum's export PR](https://github.com/huggingface/optimum-executorch/pull/214) were still open at review, with the vision encoder path incomplete. The app does not route it through a text LLM runner.

## No-weight smoke

Run `node devices/android/fixture-smoke.mjs` from the repository root. It validates the exact model/revision catalog, project wiring, and fixture response contract without fetching weights. In the app, select a model and tap **Run fixture** to verify UI-to-adapter routing. Fixture status is always `blocked` because no native model runs.

## Prepare native artifacts

Export using the upstream recipe from an ExecuTorch checkout matching the Android AAR. Keep each model at the exact revision listed in `model-pocs.json`; save the source revision, exporter commit, and artifact SHA-256 with device evidence. Never commit model artifacts or private audio.

For immutable inputs, download a local Hugging Face snapshot with `hf download <model-id> --revision <full-revision> --local-dir <private-directory>`. Point the exporter at that directory where its CLI accepts a local path. **The upstream Parakeet script currently hardcodes an unpinned model ID in both `ASRModel.from_pretrained` and `hf_hub_download`.** Change both calls to use the listed revision, or use a locally pinned snapshot, and verify the generated artifact provenance before claiming it represents the listed revision. The Whisper exporter accepts a local model path through `--model`; the preprocessor must use `--feature_size 128` for large-v3-turbo. The Qwen3 `.pte` and tokenizer must come from the same revision and a compatible ExecuTorch release. Do not rename an unrelated exported model to satisfy the asset preflight.

For SmolLM2, pin the source: `hf download HuggingFaceTB/SmolLM2-135M-Instruct --revision 12fd25f77366fa6b3b4b768ec3050bf629380bac --local-dir /private/path/smollm2-135m`. In an Optimum ExecuTorch checkout, export that **local directory** with `optimum-cli export executorch --model /private/path/smollm2-135m --task text-generation --recipe xnnpack --use_custom_sdpa --use_custom_kv_cache --qlinear 8da4w --qembedding 8w --output_dir /private/path/smollm2-export`. The [upstream example](https://github.com/huggingface/optimum-executorch#option-2-export-and-load-separately) names this model and these options, but its unpinned model ID does not prove the listed revision. Copy the generated `.pte` as `model.pte` and the pinned snapshot's `tokenizer.json` into the asset directory after checking the exported filename and Android AAR operator compatibility. Record source revision, exporter commit, quantization settings, and artifact hashes alongside physical-device evidence. Native status remains blocked until export and device inference succeed.

For Llama 3.2, obtain access to the [gated model repository](https://huggingface.co/meta-llama/Llama-3.2-1B-Instruct) and comply with its license. Download `original/consolidated.00.pth`, `original/params.json`, and `original/tokenizer.model` from revision `9213176726f574b556790deb65791e0c5aa438b6` using `hf download meta-llama/Llama-3.2-1B-Instruct --revision 9213176726f574b556790deb65791e0c5aa438b6 --include "original/*" --local-dir /private/path/llama3-2-1b`. From a matching ExecuTorch checkout, use the [documented BF16 export](https://github.com/pytorch/executorch/tree/main/examples/models/llama#option-a-download-and-export-llama32-1b3b-model): `python -m extension.llm.export.export_llm --config examples/models/llama/config/llama_bf16.yaml +base.model_class=llama3_2 +base.checkpoint=/private/path/llama3-2-1b/original/consolidated.00.pth +base.params=/private/path/llama3-2-1b/original/params.json`. Copy the generated `.pte` as `model.pte` and the **same revision** `original/tokenizer.model` into the listed asset directory. Do not label this BF16 export as quantized. For smaller assets, follow the upstream SpinQuant route only with the matching quantized checkpoint and separate provenance; renaming a different checkpoint does not establish this model/revision. On device, the text adapter uses Llama 3 chat tokens and `tokenizer.model`. Native pass and performance remain unmeasured.

## Android runtime

The default Gradle dependency is `org.pytorch:executorch-android:1.4.1` and provides the text `LlmModule` path. SmolLM2's export recipe uses custom SDPA and KV-cache operators; check that the packaged AAR is compatible with the exported `.pte`. This dependency does **not** establish Parakeet or Whisper support. The [official Parakeet Android demo](https://github.com/meta-pytorch/executorch-examples/tree/main/parakeet/android/ParakeetApp) uses a custom AAR containing `ParakeetModule`; the [official Whisper Android demo](https://github.com/meta-pytorch/executorch-examples/tree/main/whisper/android/WhisperApp) says `AsrModule` is not yet released and requires an AAR with audio JNI bindings. Build or obtain an AAR from the same ExecuTorch source revision as your `.pte`, containing the needed binding, then set `executorchAar=/absolute/path/to/executorch.aar` in a local Gradle property or pass `-PexecutorchAar=/absolute/path/to/executorch.aar`. The project substitutes that AAR for Maven. An AAR with only the Parakeet binding does not enable Whisper; verify both classes before expecting both ASR paths to work in one build.

The app uses the dedicated Parakeet `transcribe(wavPath)` and Whisper `transcribe(wavPath, callback)` APIs through a narrow reflection boundary. If the custom bindings or required assets are absent, the UI shows `blocked`. It does not attempt to treat ASR `.pte` files as LLMs. Use a 16 kHz mono PCM16 RIFF/WAVE file through **Choose WAV**. Qwen3, SmolLM2, and Llama 3.2 take a text prompt. Copied assets are cached under their immutable revision and refreshed when the installed APK changes. Native tests must run on a physical Android device with its model artifacts and compatible AAR; host-only fixture success does not establish model quality, memory, latency, or offline execution evidence.

## Current validation limits

This source tree can be checked without weights. A full Gradle build requires Android SDK and dependency access; ASR device inference additionally requires custom JNI AARs and exported artifacts. Record these as blocked until a physical run proves them. Use the repository's benchmark evidence schema only after measured device execution; the app deliberately does not emit invented benchmark JSON.
