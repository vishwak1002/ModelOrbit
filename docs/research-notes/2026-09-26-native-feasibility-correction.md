# Native POC feasibility correction — 2026-09-26

The 2026-09-18 modality decision treated `Qwen/Qwen3-VL-2B-Instruct` as verified on both phones. The cited [Optimum ExecuTorch export PR](https://github.com/huggingface/optimum-executorch/pull/214) and [ExecuTorch runner PR](https://github.com/pytorch/executorch/pull/17572) remain open. The proposed runner keeps the vision encoder in PyTorch eager because portable 5D Conv3d support is missing. Apple's [VLM exporter](https://github.com/apple/coreai-models/blob/main/python/src/coreai_models/vlm/export.py) uses a macOS export path and does not establish iPhone compatibility. The inventory now records both lanes as claimed, removes the model from the verified intersection, and keeps it available for future research. A full Android or iPhone native inference result must not be claimed from these sources.

The current cross-platform POC selection is Parakeet TDT v3, Qwen3 0.6B, and Qwen3 1.7B. The Qwen3 variants replace Qwen3-VL and Whisper in the verified selection because [Apple](https://github.com/apple/coreai-models/tree/main/models/qwen3) and [ExecuTorch](https://github.com/pytorch/executorch/tree/main/examples/models/qwen3) provide direct text-model paths. Whisper remains an experimental POC on both phones, while Qwen3-VL remains an experimental iOS lane and blocked Android lane. This is a feasibility selection, not a device benchmark.

The same text adapter in each device project also includes the source-verified Qwen3 4B revision from the inventory. Its larger size is a device practicality question until memory and latency are measured.

Source-verified export or sample code does not mean a POC was built or run. Keep native build, export, latency, memory, and task quality marked blocked or unknown until measured. The host has Xcode 26.4.1 while Apple Core AI requires Xcode/iOS 27+, and it lacks the Android SDK, ADB, Gradle, and test devices.
